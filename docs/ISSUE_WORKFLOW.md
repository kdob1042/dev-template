# Issue・PRの残件運用

一つの実装でIssueを最後まで完了できないことは許容する。ただし、途中まで実装した状態を元IssueのコメントやPR本文だけで管理し続けない。独立して実装できる残件は新しいIssueへ切り出し、PRとIssueを相互にたどれる状態にする。

## 部分実装をマージする前

1. 元Issueの受入条件を一つずつ確認し、今回完了する条件と未完了の条件を分ける。
2. 未完了の作業が独立して実装できるなら、目的、範囲、受入条件、依存関係を含む残件Issueを作る。
3. 残件Issueには元Issueと先行PRへのリンクを記載し、元IssueとPRからも残件Issueへリンクする。
4. 残件Issue本文に独立した行で`Parent: #<元Issue番号>`を記載する。これがない部分PRは元Issueを閉じない。

残件が追加改善にすぎず、元Issueの受入条件をすべて満たしている場合は、元Issueを完了にしてよい。追加改善は別Issueとして登録する。

## PR本文の書き分け

- `Closes #123`、`Fixes #123`、`Resolves #123`：このPRのマージで受入条件がすべて満たされる場合だけ使う。
- `Refs #123`：一部実装、調査、準備、または関連対応の場合に使う。
- 一つのPRで複数Issueを扱う場合は、完了するIssueと参照するIssueを一行ずつ明示する。

Draft PRでは、完了条件が確定していなければ`Refs`のままにする。受入条件と検証結果を確認した後、必要な場合だけ`Closes`へ変更する。

## マージ後の確認

- 完了対象のIssueだけがクローズされている。
- 残件Issueへ移管した場合は、元Issueがクローズされ、残件IssueがopenのままTodoで残っている。
- 元Issue、残件Issue、PRを相互に開ける。
- Projectの表示がIssue・PRの実態と一致している。`status:*`ラベルは使わない。
- CI確認済みと、実装済み・利用者受入済みを混同していない。

Project同期に失敗した場合は`docs/PROJECT_AUTOMATION.md`の復旧手順で再実行する。Project表示だけをIssue完了の根拠にせず、受入条件が残る場合は残件Issueを作ってから元Issueを閉じる。
